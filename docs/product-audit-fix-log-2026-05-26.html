Product Audit Fix Log

May 26, 2026. Follow-up to docs/product-audit-2026-05-26.html.

Fixed: the broken test paths, the missing draft events page, the inventory stock error, the accessibility findings, the browser console warnings, the first round of slow first-load behavior, the worker load-test misses, the academic day-schedule API error, the noisy speed-test setup, and the first real IT/maintenance desktop and mobile workflow issues found during the audit.

What Was Fixed

  • /draft-events no longer returns a missing page. It now sends users to the events area with the draft filter in the URL.
  • Campus, inventory, and ticket smoke tests now use the correct local environment, current user fields, CSRF token handling, and current campus field names.
  • Inventory checkout now returns a clear “not enough stock” response instead of a server error.
  • Hidden sidebar links are no longer left focusable for screen readers.
  • The mobile IT filter button now has a readable name for screen readers.
  • The dashboard task progress bar now has a readable name for screen readers.
  • Several IT and maintenance tab panels were cleaned up so hidden panels do not confuse assistive technology.
  • Calendar event colors and muted text colors were darkened enough to pass contrast checks.
  • Supabase realtime is now quiet in local audit runs. It stays off unless NEXT_PUBLIC_SUPABASE_REALTIME_ENABLED=true is set, and normal polling still works.
  • The weather widget no longer turns a slow outside weather service into a failed browser request. It now shows a friendly unavailable state.
  • Disabled messaging no longer creates a failed background request when the app checks unread message counts.
  • Several background requests now wait until after the first page load settles, including broad cache preloading, trial status, sidebar approval badges, and mobile unread-message checks.
  • The app now shares the first /api/auth/me result across auth consumers, reducing duplicate auth calls during page startup.
  • Closed dashboard drawers no longer fetch event form/template setup data until a user opens them.
  • The PM calendar redirect now happens on the server instead of causing a browser-side redirect spin.
  • The browser audit now ignores harmless canceled Next.js _rsc redirect requests while still counting real failed API and page requests.
  • Calendar now delays filter setup, adjacent-month prefetching, calendar subscriptions, school lists, and user campus lists until the user needs them or the page has settled.
  • Maintenance now mounts only the active tab. The dashboard no longer loads the PM calendar in the background.
  • Maintenance offline ticket/asset caching now waits until after first load, instead of competing with the page the user is trying to open.
  • IT ticket assignment now accepts the app's real user ID format. It was incorrectly expecting UUIDs.
  • A repeatable worker workflow audit script now creates real IT and maintenance worker accounts, runs their job flows, records timings, and writes evidence to docs/audit-artifacts/worker-workflows.json.
  • The worker audit now creates the IT Coordinator and Head of Maintenance roles when the test org is missing them, with the permissions needed for the job.
  • The worker audit now also creates the default IT Support and Facility Maintenance teams when the test org is missing them, so mobile role tabs work correctly.
  • The mobile workflow mode now runs from a phone-sized viewport and writes evidence to docs/audit-artifacts/mobile-worker-workflows.json.
  • The maintenance worker role now includes knowledge-base read access, because the work order detail page shows knowledge-base suggestions during the job.
  • The IT and maintenance worker load test now passes all speed thresholds after short, organization-safe caching was added to busy read-only worker endpoints.
  • The comprehensive speed test now uses current routes: /api/auth/me, /api/settings/campus/spaces, dated board-report requests, and dated day-schedule requests.
  • The academic day-schedule API no longer returns a server error. The service now uses the schema's real schoolId and school fields instead of the old campus field names.
  • The focused benchmark script now includes inventory, planning seasons, events, and maintenance knowledge base, and it can run shorter or longer checks with BENCH_DURATION and BENCH_VUS.
  • The route cache now shares identical in-flight reads during traffic bursts, so several users asking for the same list at the same time do not trigger duplicate database work.
  • Middleware now passes verified user details to API routes, so routes do not have to verify the same token twice during normal requests.
  • A clean local E2E runner now builds once, starts a production server on an open local port, points Playwright at it, and shuts it down after the run. This prevents E2E tests from sharing .next with a dev server that is being rebuilt.
  • Local production-mode auth cookies now work on localhost. The app no longer sets .lionheartapp.com secure cookies when the configured app URL is local.
  • Gemini embeddings now default to the current gemini-embedding-001 model, can be configured with GEMINI_EMBEDDING_MODEL, and can be disabled with AI_EMBEDDINGS_ENABLED=0.
  • The clean local E2E runner disables background embeddings by default, so API tests do not depend on an outside AI service.
  • The route inventory now treats /api/status and the Stripe webhook as public routes, matching the real middleware rules used by the app.
  • The IT page now lazy-loads the board, list view, insights dashboard, settings tools, QR manager, form editor, AI intake drawer, manual request drawer, and ticket detail drawer instead of shipping all of that code on first load.
  • The maintenance page now lazy-loads PM calendar/list tools, the PM schedule wizard, submit-only request view, routing settings, and form editor instead of loading them with the dashboard.
  • The dashboard now lazy-loads drawers, event creation panels, event project modals, onboarding checklist, planning-season widget, and task drawer instead of shipping all of that code on first load.
  • The dashboard's old unused ticket-create drawer and old unused maintenance wizard were removed from the page bundle.
  • The IT Help Desk board now has a clear New Request action, so IT workers can create a ticket without switching views.
  • The IT AI request drawer now keeps a Manual Form escape visible, so a worker is never trapped in the AI path.
  • The manual IT request form now refreshes the IT board/list after submit, so the new ticket appears right away.
  • Event creation now uses the current approval-config schema. The old campus-based approval config path was updated to the current school-based path, while still accepting old campus input for compatibility.
  • Organization-wide approval defaults now work when no specific school is selected.
  • Event conflict detection now writes audit activity under the real event creator instead of a fake system user, preventing non-fatal activity-log errors.
  • Event and dynamic form labels now connect to their fields, which makes browser testing and screen-reader navigation more reliable.
  • Old Gemini model references were updated to gemini-2.5-flash so AI routes do not call the retired gemini-2.0-flash model.
  • The dashboard "View all tasks" action now meets the minimum mobile tap-target size.
  • Settings Members browser tests now follow the current Settings side-panel buttons instead of old tab/link paths.
  • Invite-member validation coverage now checks the real browser email validation state inside the active invite drawer.
  • Super-admin browser coverage now checks the real daily navigation and Settings side panel used by admins today.
  • The app now assigns the right dashboard mode from /api/auth/me: admin, IT, maintenance, A/V, or default member view. Regular members no longer get the admin calendar dashboard by mistake.
  • The dashboard no longer requests calendar/event-project data for users who are not allowed to use those admin calendar views.
  • The background auth prefetch no longer warms calendar data for every user, which avoids unnecessary permission noise and background work.
