Lionheart Feature Worklist

May 27, 2026. Plain-English follow-up to the product audit and role/team checks.

Current state: the main tested paths are in much better shape. The biggest remaining work is not one broken screen. It is finishing coverage on unlabelled route permissions, real-record pages, and longer speed testing.

What Looks Good Right Now

  • Login, signup, dashboard, tickets, events, forms, settings, mobile navigation, role flows, campus selector, link crawling, and link checking passed the broad browser run.
  • IT and maintenance workers can complete realistic job flows on desktop and phone-sized screens.
  • Super Admin, Admin, IT Worker, Maintenance Worker, A/V Worker, Teacher/Staff Member, and Viewer were checked for the right navigation and route access.
  • Automated accessibility checks passed across authenticated and public pages.
  • Visual checks passed across the first 60 pages after reviewing and saving healthy baselines.
  • Random-click testing passed across the first 24 crawlable pages.
  • The corrected production-mode speed benchmark passed all 720 checks with no failed requests.
  • The longer 60-second speed benchmark passed 5,900 checks with no failed requests. Most endpoint medians were under 20 ms. Login was about 317 ms median because secure password checking is intentionally expensive.
  • The unit test suite passed 952 checks.
  • The full Chromium browser suite passed 194 checks with 9 intentional skips.
  • Firefox, WebKit/Safari, and mobile Chrome passed the login, dashboard, and mobile layout smoke pass with 100 checks and 3 intentional skips.

Features That Still Need Work Or Review

Permission Review

  • 189 logged-in route handlers need a human pass. The automated permission tests passed, but these routes do not declare a clear permission label in the inventory.
  • Each one should be marked as one of these: admin-only, team-only, user-owned, shared for all logged-in users, or intentionally public.
  • Any route that changes data should get the strictest review first.

Lint Cleanup

  • Full lint is not clean yet. A few safe errors were fixed during this pass, but the larger backlog remains.
  • The biggest lint item is raw database access inside 154 API route files. The exact list is in docs/audit-artifacts/raw-prisma-route-review-2026-05-27.txt.
  • Some of these are correct for auth, cron, public-token, or platform work, but each route needs an explicit reason or a safer scoped database client.
  • There are also many image and React dependency warnings. They are lower risk than permission and route review, but should be cleaned up steadily.

Real-Record Pages

  • 22 dynamic pages need deeper scenarios. These pages require a real event, ticket, form, device, user, or other record ID.
  • The next pass should create real records, open each detail page, edit the record, save it, reload it, and confirm the right role can still see it.

IT Work

  • Keep testing the IT queue with more ticket types: device issue, password reset, network issue, loaner device, and security incident.
  • Confirm IT workers can find, filter, assign, pause, complete, and reopen work without needing admin-only screens.
  • Confirm IT managers can use admin/reporting tools without exposing those tools to normal IT workers.

Maintenance Work

  • Keep testing work orders with photos, labor time, material cost, repeat repairs, preventive maintenance, and QA closeout.
  • Confirm maintenance workers can finish a job from mobile without needing the desktop-only settings area.
  • Confirm maintenance leads can assign, approve, and report without giving every worker manager access.

Events And Approvals

  • Approval routing is working better, but needs more real-school coverage.
  • Test events that need A/V, facilities, admin approval, no approval, conflict handling, and last-minute changes.
  • Confirm people who are not on an approval team see a clear no-access message, not a broken queue.

Speed

  • The corrected short benchmark and 60-second benchmark passed. Before launch confidence, run a longer 30-60 minute soak with normal traffic.
  • Keep watching any page that grows past about 300 kB of first-load JavaScript.
  • Keep IT, maintenance, dashboard, calendar, and event pages on the speed watchlist because they are daily-use paths.

Role Scenarios Already Run

  • Super Admin: full desktop work area, Approvals mobile tab, admin settings, IT, maintenance, and A/V approvals.
  • Admin: dashboard, calendar, forms, approvals, Leo, and Approvals mobile tab.
  • IT Worker: IT dashboard mode, IT desktop navigation, IT Tickets mobile tab, and job workflow.
  • Maintenance Worker: maintenance dashboard mode, maintenance desktop navigation, Work Orders mobile tab, and job workflow.
  • A/V Worker: A/V approval access and no hidden approval queue errors.
  • Teacher/Staff Member: normal dashboard and ticket path without admin work tools.
  • Viewer: dashboard load without avoidable campus permission errors.
