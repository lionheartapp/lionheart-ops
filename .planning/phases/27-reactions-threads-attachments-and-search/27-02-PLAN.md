<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> upload-url API | User-supplied fileName, mimeType, fileSize cross into signed URL generation |
| client -> Supabase Storage | File binary uploaded directly to storage via signed URL |
| message display -> storageUrl | URL from DB rendered as img src or download href |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-06 | Tampering | POST /upload-url | mitigate | Zod validates fileSize max 25MB, mimeType allowlist, fileName sanitized (strip path chars, max 255 chars) |
| T-27-07 | Spoofing | File upload | mitigate | Signed URL scoped to org path in Supabase Storage; withAuth ensures authenticated user; channel membership verified |
| T-27-08 | Info Disclosure | storageUrl in messages | accept | messaging-attachments bucket is public-read for simplicity; files are scoped by orgId path prefix; acceptable for staff-only messaging |
| T-27-09 | Denial of Service | File upload | mitigate | 25MB limit enforced both client-side (useFileUpload) and server-side (Zod schema); single file at a time |
| T-27-10 | Elevation | Attachment creation | mitigate | MessageAttachment record only created via sendMessage which verifies channel membership; storageUrl validated as matching expected Supabase path prefix |
| T-27-11 | Tampering | XSS via fileName | mitigate | fileName rendered as text content in React (auto-escaped); never used in dangerouslySetInnerHTML; sanitized on server before storage |
</threat_model>
