<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> reaction API | User-controlled emoji string crosses into DB write |
| client -> pin API | User attempts to pin/unpin messages they may not have permission for |
| client -> mute API | User toggles mute on channels they belong to |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-01 | Tampering | POST /reactions | mitigate | Validate emoji with Zod (z.string().min(1).max(32)); verify channel membership before creating reaction |
| T-27-02 | Elevation | PATCH /messages pin | mitigate | Check MESSAGING_CHANNELS_MODERATE permission or channel owner/admin role before allowing pin/unpin |
| T-27-03 | Spoofing | All reaction routes | mitigate | withAuth wrapper verifies JWT; reaction is always created with ctx.userId, never client-supplied userId |
| T-27-04 | Info Disclosure | GET /pins | mitigate | Verify requesting user is a channel member before returning pinned messages (org-scoped prisma + membership check) |
| T-27-05 | Denial of Service | POST /reactions | accept | Unique constraint (messageId, userId, emoji) prevents duplicate spam; rate limiting deferred to Phase 28 |
</threat_model>
