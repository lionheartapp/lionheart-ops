**messagingPreferenceService.ts** — shared preference query logic per D-12:

Export three functions:

1. `getChannelPreference(userId: string, channelId: string): Promise<{ level: string; emailDigest: boolean }>` — queries MessagingNotificationPreference for this user+channel. Returns `{ level: "all", emailDigest: true }` as default if no row exists.

2. `shouldNotify(userId: string, channelId: string, isMention: boolean): Promise<boolean>` — returns true if the user should receive a notification for this channel. Logic: get preference; if level = "none" return false; if level = "mentions" return isMention; if level = "all" return true.

3. `getUserDigestPreference(userId: string): Promise<{ enabled: boolean }>` — checks if the user has any channel with emailDigest = true. Returns `{ enabled: true }` if at least one channel has emailDigest on (used by digest cron).

Use `rawPrisma` for these queries since they may be called from contexts outside runWithOrgContext (e.g., cron jobs, notification service).

Create POST and DELETE endpoints for push subscription management per D-07 and D-09.

**POST /api/messaging/push-subscription:**
- Auth via getUserContext + runWithOrgContext
- Zod schema: `{ endpoint: z.string().url(), keys: z.object({ p256dh: z.string().min(1), auth: z.string().min(1) }) }`
- Validate endpoint is a valid HTTPS URL (push endpoints must be HTTPS). Reject non-HTTPS endpoints with 400.
- Upsert PushSubscription: `prisma.pushSubscription.upsert({ where: { userId_endpoint: { userId: ctx.userId, endpoint } }, create: { userId: ctx.userId, endpoint, p256dh: keys.p256dh, auth: keys.auth }, update: { p256dh: keys.p256dh, auth: keys.auth } })`
- Return ok({ subscribed: true })

**DELETE /api/messaging/push-subscription:**
- Auth via getUserContext + runWithOrgContext
- Zod schema: `{ endpoint: z.string().url() }`
- Delete: `prisma.pushSubscription.deleteMany({ where: { userId: ctx.userId, endpoint } })`
- Return ok({ unsubscribed: true })

Security: validate endpoint URL starts with "https://" to prevent subscription to non-secure endpoints. The endpoint string is opaque to us — it's a browser push service URL — but it MUST be HTTPS per the Web Push protocol.
