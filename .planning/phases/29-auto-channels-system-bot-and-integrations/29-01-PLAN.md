**Create `src/lib/services/autoChannelService.ts`:**

Per D-01, D-02, D-03 (team channels):
- `createTeamChannel(teamId: string, teamName: string, botUserId: string): Promise<string>` — creates a PUBLIC channel with `name: teamName`, `sourceType: 'team'`, `sourceId: teamId`, `createdById: botUserId`. Uses org-scoped `prisma`. Returns channelId. Must be idempotent: check if a channel with `sourceType='team'` and `sourceId=teamId` already exists first; if so return its id.
- `syncTeamMembers(teamId: string, botUserId: string): Promise<void>` — finds the auto-channel for this team (by sourceType+sourceId), fetches all UserTeam rows for the team, then adds missing members and removes stale members. Uses `prisma.channelMember.create` and `prisma.channelMember.delete` directly (not channelService.addMember which has permission checks). Always keeps the bot user as a member.

Per D-04, D-05, D-06 (school channels):
- `createSchoolChannel(schoolId: string, schoolName: string, botUserId: string): Promise<string>` — creates PUBLIC channel with `name: "{schoolName} Staff"`, `sourceType: 'school'`, `sourceId: schoolId`, `createdById: botUserId`. Idempotent same as team.
- `syncSchoolMembers(schoolId: string, botUserId: string): Promise<void>` — finds auto-channel for this school, fetches all active (non-deleted) users with `schoolId` matching, adds missing / removes stale. Keeps bot as member.

For both sync functions: use `prisma` (org-scoped). The slug for auto-channels should be generated from the name using the same `toSlug` helper pattern as channelService (copy the helper locally or import — prefer copy to avoid coupling).

**Create `src/lib/services/systemBotService.ts`:**

Per D-07:
- `getOrCreateBotUser(orgId: string): Promise<string>` — uses `rawPrisma` to find a user with `isBot: true` and `organizationId: orgId`. If not found, creates one with `email: 'bot@lionheart.internal'`, `firstName: 'Lionheart'`, `lastName: 'Bot'`, `isBot: true`, `status: 'ACTIVE'`, `organizationId: orgId`. Returns the bot user ID.

Per D-08:
- `postToChannel(channelId: string, orgId: string, content: string): Promise<void>` — gets the bot user ID via `getOrCreateBotUser(orgId)`, then calls `sendMessage(channelId, botUserId, { content })` from messageService. Wrap in try/catch — bot post failures should log but not throw (fire-and-forget for non-critical alerts).

Per D-10:
- `postTicketStatusChange(ticketId: string, ticketTitle: string, oldStatus: string, newStatus: string, teamId: string | null, orgId: string): Promise<void>` — if teamId exists, find the team's auto-channel (sourceType='team', sourceId=teamId), then postToChannel with a formatted message like: "**Ticket Update** — _{ticketTitle}_ status changed from {oldStatus} to {newStatus}. [View ticket](/tickets/{ticketId})"
- `postEventApproval(eventId: string, eventName: string, schoolId: string | null, orgId: string): Promise<void>` — if schoolId, post to school auto-channel; otherwise find a general channel or skip. Message: "**Event Approved** — _{eventName}_ has been approved. [View event](/events/{eventId})"
- `postMaintenanceAlert(ticketId: string, ticketTitle: string, teamId: string | null, orgId: string): Promise<void>` — similar to ticket, posts to team auto-channel. Message: "**Maintenance Alert** — _{ticketTitle}_ requires attention. [View ticket](/tickets/{ticketId})"

All post functions are async fire-and-forget. Import `runWithOrgContext` for the channel lookups. Use `rawPrisma` only in `getOrCreateBotUser`; use `prisma` (org-scoped via runWithOrgContext) for channel lookups.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Bot user creation | Bot must not be impersonable — email is internal-only, isBot flag prevents login |
| Auto-channel membership sync | Must not grant access to channels the user shouldn't see (org-scoped Prisma enforces) |
| Source context links | sourceId must be validated as belonging to same org before display |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-29-01 | Spoofing | systemBotService.getOrCreateBotUser | mitigate | Bot user email uses @lionheart.internal domain (not routable), isBot=true prevents auth login flow (no passwordHash set) |
| T-29-02 | Elevation of Privilege | autoChannelService.syncTeamMembers | mitigate | Sync reads UserTeam table (org-scoped) — only users already in the team get channel access; no external input controls membership |
| T-29-03 | Information Disclosure | sourceId on Channel | mitigate | sourceId is only rendered in UI for same-org users; all channel reads are org-scoped via Prisma extension |
| T-29-04 | Tampering | Bot message content | accept | Bot messages use hardcoded templates — no user input flows into content except entity names which are already org-scoped data |
</threat_model>
