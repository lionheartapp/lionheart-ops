CREATE OR REPLACE FUNCTION broadcast_new_message()
RETURNS TRIGGER

END;
$$;

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> /api/auth/token | Unauthenticated request could attempt token extraction |
| Token response -> browser memory | JWT exposed in response body (necessary for Supabase client) |
| Postgres trigger -> Supabase Realtime | Broadcast payload contains message content |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-01 | Information Disclosure | /api/auth/token | mitigate | Return only the JWT string (no user data beyond what's in claims). Set Cache-Control: no-store to prevent caching. Require valid auth cookie or bearer token. |
| T-25-02 | Spoofing | /api/auth/token | mitigate | Verify JWT signature with AUTH_SECRET before returning. Invalid/expired tokens get 401. |
| T-25-03 | Information Disclosure | broadcast_new_message trigger | accept | Payload contains message content but is only delivered to subscribers on the matching topic. Topic includes orgId for defense-in-depth. Channel-level subscription auth handled by Supabase Realtime + RLS. |
| T-25-04 | Elevation of Privilege | broadcast topic naming | mitigate | Topic includes orgId prefix (msg:{orgId}:{channelId}) so even if a client guesses a channelId from another org, the topic won't match their subscription. |
</threat_model>
